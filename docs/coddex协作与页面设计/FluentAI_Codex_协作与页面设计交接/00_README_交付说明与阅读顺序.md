## Codex 阅读顺序

1. **先读 `03_给Codex的统一协作与实施指令.md`**，理解当前要做什么。
2. 阅读 `01_Codex协作协议_需求与实施权限.md` 与 `04_确认决策与需求冲突处理.md`，锁定业务决定和授权边界。
3. 阅读 `02_工程辅助Agent_V1_前端页面与交互规格.md` 并打开预览 HTML，理解界面。
4. 参考 `05_页面实现检查表.md` 做实现自检。
5. **再结合此前已交付的《Fluent 工程辅助 Agent V1 设计包》**，核对 Agno、两种算法、Prompt、知识库、输入输出 Schema；若仓库没有该包，Codex 应标明缺少的资料，而不是虚构文件内容。
6. 阅读现有 Electron / FastAPI / Fluent 仓库的真实代码及项目指令，优先复用现有组件。

## 关键决策及边界

- **本交接包是先前 Agent V1 业务/算法设计包的“页面和协作补丁”**，不是重做系统、更不是覆盖其它模块（模板库、任务进程、我的模型等）的产品需求。
- **明确已确认的产品决定高于旧草案的冲突建议**；技术事实以仓库真实代码、实际 Fluent/PyFluent 测试为准，未验证要明示。
- UI 设计中的尺寸和技术组件命名是**设计建议**，Codex 可以因现有组件或窗口尺寸合理调整，但必须保持用户交互、布局逻辑与功能状态完整。
- 默认**在当前已获批开发范围内连续推进**；只有新增重要业务行为、破坏性变更、付费或密钥授权、不可逆操作等高影响问题才中断请示。

## 两处主要页面

**页面 A：模板新建/编辑页** — 保留原 Fluent 参数/步骤，右侧工程辅助 Agent（默认约 380–440px，可收起，窄窗口变 Drawer）。消息中部独立滚动，底部输入区固定；支持快捷问题、图片、只读参数卡、两方法选择卡、真实工具事件及推荐卡。

**页面 B：现有“设置”页** — 往下滚动显示“AI 模型配置”，用于全平台一个当前生效的大模型 API；文本/工具/图片/流式能力测试及降级，其他 Agent 不分别配置模型。

**额外注意：模板库首页“上方模板库65% / 下方任务进程35%”是另一页面的上下布局，不得套到模板编辑页的左右分栏。**

## 交接方式

将整个文件夹复制进现有仓库的文档目录（例如 `docs/requirements/agent-ui-codex/`），打开 `03_给Codex的统一协作与实施指令.md`，把其中“发给 Codex 的话”整体粘贴进当前 Codex 会话。

本包的 HTML 预览只用来展示界面，不代表已接入模型、工具或 Fluent。真实代码的修改和测试应由 Codex 在实际仓库里完成。

## 三、目前已锁定的页面设计

**页面 A — 模板编辑页右侧工程辅助 Agent**：保留现有 Fluent 表单与工作流，右侧可收起、默认约 380–440px 的聊天面板。上方标题、全局模型状态和能力查看；中间独立滚动消息，能显示首次/边界层步骤引导、图片附件、已识别参数只读摘要、Uniform/Smooth 方法比较选择、真实工具运行卡、推荐参数卡；底部固定 `+附件 / 多行输入 / 发送或停止`。窄窗口自适应，不能把 Fluent 表单挤坏。点击快捷问题应真正发送，不是装饰。

**页面 B — 现有设置页底部“AI 模型配置”**：在原设置页面**向下滚动可见**，填供应商/Model ID/Base URL(按需)/API Key；可测试连接和文本、工具、图片、流式能力。全平台只有一个当前生效模型 API，工程辅助与未来拓展台共用；模型能力不足允许降级。**不另建模型管理侧边栏或每模板模型配置。**

注意：模板库主页“上方 65% 模板库 + 下方 35% 任务进程”属于**另一页面**，不是 Agent 编辑页的左右比例。

## 四、V1 工程辅助功能的最终范围

采用 Agno，AI 做工程方法判断，已注册的 Python 工具做真实数值计算，后端 Schema 做单位/参数/权限校验。专业知识**按需检索**。Prompt 使用精简通用版 + 文丘里专业版，不要每轮注入完整需求文档。

只保留两个计算：Smooth 层数（`first_yplus、target_outer_yplus、growth_rate`）；Uniform 首层高度（`ρ、μ、特征速度 U、特征直径 D、目标 first y+`）。**不强制求喉部局部速度，不新增喉部速度或侧支流量工具。**复用已有算法，先核对真实代码与计算口径。用户可选择两种方法任意分支；参数明确的文字输入直接确认，图片识别不确定项和 AI 假设再确认。

每次工具调用的实际输入、结果、单位、算法版本和警告必须可核查；Fluent 字段映射未经验证时标明“工程估算/待核验”，不得虚构“可直接填写”。用户**自行填写 Fluent 模板**，Agent 不直接改写表单、生成/注册代码或执行任意 Python。

## 五、你下一步应该怎么做

1. **快速核查现状**：定位模板编辑页、设置页、已有 UI 组件、模型配置、Agno/工具、计算脚本和 Fluent 参数字段，给出简短“已具备/需改造/缺失/待核验”表。不要在这一步无限深入非关键的通用架构研究。
2. **页面实施**：在保留原 UI 风格基础上，实现/完善右侧 Agent 面板、真实交互控件与设置页 API 配置区域；优先复用现有组件、接口与样式。
3. **功能闭环**：通用聊天 → 专业引导 → 图片/文字参数 → 方法选择 → 缺参追问 → 真实工具计算 → 结果卡及历史恢复。能提前完成并验证的部分，不必等其它未决事项。
4. **验证**：使用 05 检查表逐项验收。不要因为 HTML 预览可以点击，就声称真实 Agno 或 Fluent 已接入。
5. **汇报**：输出本轮完成的界面/功能、修改的文件路径、可复现验证结果、仍需技术核实的事项、风险和下一步；重要代码变更要更新开发日志。遇到缺陷时先复现和查根因，再做最小修复并回归。

如果我此前只让你进行只读审查，而尚未明确授权你开始编码，则先提交实施计划与拟修改范围，等待我授权；**在当前已有明确开发授权的部分，可以持续推进，不再为普通实现细节反复征求确认。**

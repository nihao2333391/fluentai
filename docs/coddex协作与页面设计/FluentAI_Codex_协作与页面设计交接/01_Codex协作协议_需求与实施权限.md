# 01｜Codex 协作协议：需求理解、技术自主权、过程记录与沟通原则

**适用范围：本 Fluent AI 工程内已明确授权的开发工作；尤其工程辅助 Agent V1。**

## 1. 改变协作模式：从“不断征询”转为“按规格实施”

此前已完成大量产品对齐。Codex 下一阶段应主动承担软件工程师职责：**读取需求 → 审查已有实现 → 自主选择常规技术细节 → 最小改动开发 → 验证 → 记录 → 报告**。不能把每个实现细节都改成 A/B 选择题问用户，也不能因为存在某项“待技术验证”就停止所有不相关开发。

### 分级处理

| 类型 | 例子 | Codex 应当做什么 |
|---|---|---|
| **A：已确认业务决定** | 统一模型 API、Agent 只读推荐、两种工具、不强制喉部速度、按需知识检索 | 直接遵守，不重复询问 |
| **B：常规技术决策** | React 组件拆分、内部 hook、SSE 或已有流式方案、参数 DTO 的具体实现、日志字段 | **结合代码自行选择成熟方案**，在报告记录理由，不要求用户逐项批准 |
| **C：可验证技术事实** | Agno 当前版本 API、工具签名、Fluent 设置字段、图片模型能力、前端组件是否存在 | **先检查真实代码/文档/测试**，报告证据，必要时提出兼容适配；不把它当产品问题反复问用户 |
| **D：重大产品/风险决策** | 改变核心功能、增加收费 API、自动写入 Fluent、删除用户数据、不可逆迁移、改变用户已确认行为 | **暂停相关变更、用简短选项询问用户**；不影响的模块继续推进 |

如果能通过读取现有设计文档和代码回答，就**不要问用户重复的问题**。如果涉及普通技术实现，Codex 提供合理默认并直接实施已获授权部分。若仍需问用户，一次聚焦 1–2 个真正阻断项，写清影响、建议默认值，以及尚可继续推进的工作。

## 2. 先读文档，再查代码，然后开工

开工前检索相关规范与项目现有 README/AGENTS 指令、已有模块、API 和配置文件。输出一张简短的“需求—现状—差距”对照表。对新加依赖/新表/新状态机先查是否已经有现成能力，优先复用 Agno、现有 UI 组件、FastAPI DTO 与 Fluent 调用链。

**不做未经批准的全仓重构**；能够通过薄适配层、少量组件和已有服务完成，就不要重新搭一套微服务架构。改造不得破坏已能运行的模板、模型导入、Fluent Meshing 工作流。

## 3. 实施分阶段，但不要每个小阶段都停下来提问

建议单个功能回合包含：

1. **需求核对**：引用文档相应章节，说明输入、输出、验收点。
2. **方案与风险**：指出将修改哪些文件、复用什么、还存在哪项真实未知。
3. **开发**：在用户已授权的范围内实现，保持变更最小。
4. **验证**：运行合理的单测/构建/静态检查（避免执行未经同意的真实耗资源 Fluent 任务）。
5. **验收报告**：列实际功能、测试结果、剩余限制和下一步。

不应只输出“我做完了”，而不说明能否实际运行。涉及第三方模型 API 的测试可能产生费用，采用安全、低成本、小规模样例；未经用户授权不要运行大规模付费调用。

## 4. 缺陷处理与文档习惯（重要）

遇到 Bug 时遵循：**复现现象 → 定位代码和数据流 → 分析根因 → 给出最小修复 → 测试回归 → 写简短修复记录**。避免只调整 UI 文案掩盖后端问题，或用虚假“已连接/已执行”状态代替真实功能。

每次有实质代码改动，应在仓库现有开发日志或 `docs/dev-log/`（若无且允许新增）留下：时间、目标、涉及文件、核心变更、影响范围、执行的验证、未通过项和剩余风险。较大设计变更应同步更新对应需求与数据契约，标记旧决定被什么取代。

对于用户可理解的汇报，优先使用自然中文，先说实际完成了什么/哪里可试，再列技术细节。不是把所有框架源码原样堆给用户。

## 5. 必须如实报告的边界

- 未实际调用 Python 工具，就不能说“工具已完成计算”。
- Fluent 参数只在运行/代码核对后标注“可直接填写”；不能凭习惯猜字段。
- API Key 不能泄露到日志或前端明文持久化。
- 用户未批准自动修改 Fluent 表单，Agent 只能提供建议。
- 模型不支持工具调用仍可聊天，但可靠计算要降级并解释。
- 页面图片/HTML 预览是视觉依据，不等于真实运行完成。
- 网络、模型配置、文档来源或计算脚本缺失时，列出具体缺口，并尽可能继续完成不依赖它的前端或测试。

## 6. Codex 完成每轮工作的标准汇报格式

**本轮完成**：哪些可操作功能，在哪个页面。  
**改动文件**：文件路径与用途。  
**关键实现**：涉及哪些既有模块、接口、数据契约。  
**验证结果**：执行了哪些检查、是否通过；哪些未测试及原因。  
**风险与待确认**：仅真正阻断的问题，区别产品决策与技术核验。  
**下一步**：在既定范围内最有价值的接续任务。

## 7. 当前 V1 优先级

优先完成能真正演示的闭环：

`模板编辑页右侧 Agent → 全局模型配置 → 首次欢迎/聊天 → 专业方法比较 → 缺参追问 → 现有两类 Python 工具真实调用 → 推荐卡 → 用户手动填写 Fluent`。

知识按需检索、图片确认和会话恢复在闭环形成后逐步强化。不要在 V1 中加入喉部速度求解器、复杂区域管理、自动工具生成/注册、拓展台管理页面或 Agent 一键改 Fluent 表单。

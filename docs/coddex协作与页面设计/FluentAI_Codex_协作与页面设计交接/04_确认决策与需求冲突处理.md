## 2. 旧方案被最新决定替代的地方

- 旧版“Uniform 必须知道喉部局部速度/目标壁面区域才能开始”→ **取消硬性要求**，现在只使用本次已指定的特征速度 U、特征直径 D，并诚实说明计算假设和适用区域。
- “用户每输入一个明确参数都要再点击确认”→ **取消重复确认**；只有图片提取不确定值、模糊文字或工程假设才追问确认。
- “每轮问答必须检索专业知识/展示完整报告”→ **按需检索、按需展开**，概念问题直接解释。
- “每个 Agent/拓展台分别配置 API”→ **统一设置页全局 API**。
- “所有模型必须通过工具测试才能启用”→ **允许降级启用**，不会工具则不做可信计算。
- “Agent 可自动填写或改写 Fluent 表单”→ **V1 不做**。
- “Prompt 内写满算法/持久化/权限逻辑”→ **移入确定性工具、数据 Schema 和后端业务服务**。

## 3. 不可当成既有事实的内容

- Agno 当前仓库安装版本、流式/Session API、WebSearchTools/其他搜索后端的实际依赖及网络可达性。
- 用户已有 `boundary_layer_layers.py` / Uniform 计算封装的文件路径、函数名、默认参数、算例是否与文档完全一致。
- Fluent 2025 R2 中 Uniform First Height、Smooth Transition Ratio 等实际面板和 PyFluent API 的可用性。
- 现有 Electron 设置页/模板编辑页具体组件名、路由、状态保存、附件/聊天实现。

这些必须由 Codex 先调查真实代码。常规技术选择可以自主实施；如果真实技术实现与产品意图矛盾，则报告最小适配方案。

## 4. 当前暂不推进的内容

复杂喉部局部速度/侧支流量算法、CAD 自动识别所有尺寸、专门的区域参数数据库、多会话管理页面、AI 生成并注册任意工具、自动代填 Fluent、拓展台知识管理 UI、完整 CFD 网格质量自动闭环优化。

保留全系统的其它产品决定：一个原始模型可重复应用多个模板；任务卡以模板为主标题、模型文件为副标题；任务完成仍保留；任务删除默认保留产物并允许勾选清理；任务失败重试策略仍待定。这些不是本次 Agent UI 工作范围，不需要顺手修改。

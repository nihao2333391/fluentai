# Fluent AI｜工程辅助 Agent V1 前端页面与交互规格

**版本：V1.0 设计提案（供 Codex 按现有代码实现）**  
**依托页面：现有“模板创建/编辑”页、现有“设置”页**  
**设计目标：保留既有 Fluent 工作流表单；使用右侧 Agent 面板完成工程辅助；模型 API 配置集中在“设置”页靠下区域。**

## 0. 这份文档补充了什么

此前专项设计包规定了行为和数据 Schema，但还缺少页面结构、尺寸、组件清单、不同状态下的视觉与动作。此文档将 Agent 前端明确为两处真实 UI：

1. 模板编辑/创建页：右侧工程辅助 Agent（最重要），不是新开的整页聊天应用；
2. 系统「设置」页向下滚动出现一块“AI 模型配置”，没有独立模型管理导航。

**模板库首页“上方 65% / 下方 35% 任务进程”属于另一个页面，不是编辑页右侧 Agent 的分栏比例。**

V1 拓展台仍为占位页面，不因本项设计提前增加真实工具管理 UI。

## 1. 视觉设计原则

- 与现有 Fluent AI 截图对齐：浅灰蓝应用背景、白色内容卡、细边框、蓝色为主操作色、绿色仅用于真正成功/已就绪的状态；不要完全改造项目全局样式。
- 清晰的桌面应用层级：左侧原导航 → 编辑页主内容区 → 左工作流表单 / 右 Agent；顶部全局标题/连接状态沿用。
- Agent 面板是**固定可用高度 + 内部独立消息滚动容器**，输入框固定在面板底部；编辑页左侧拥有自己独立滚动，互不干扰。
- 避免设计成移动端大号聊天泡泡。工程数值、表格、来源及工具调用采用密度适中的小卡片。
- 不增加“Agent 提供者/每模板 API/代码生成/工具注册”之类的设置按钮；当前 Agent 只消费已配置能力。

## 2. 页面 A：模板创建/编辑页 + 工程辅助 Agent

### 2.1 桌面信息架构

```text
┌────────────────────────────────── Fluent AI / Electron 顶栏 ──────────────────────────────────┐
│ 左侧原导航  │ 编辑网格划分模板       [已自动保存] [目录名称]              [保存/发布]         │
│             ├───────────────────────────────┬───────────────────────────────────────────┤
│ 模板库      │ 模板名称、模型类型、参考模型等  │ [工程辅助 Agent] [模型名·只读] [能力] [收起]│
│ 我的模型    │ 现有 Fluent Meshing 步骤条     ├───────────────────────────────────────────┤
│ 设置        │                               │ 一次性欢迎卡 + 快捷问题                   │
│             │ 左侧现有步骤参数配置表单        │ 用户消息 / 图片缩略图                      │
│             │ （如 Add Boundary Layers）     │ 已识别参数摘要（可折叠）                  │
│             │                               │ Smooth / Uniform 比较卡及选择              │
│             │                               │ 工具运行事件 + 参数推荐结果卡              │
│             │                               │                                           │
│             │                               ├───────────────────────────────────────────┤
│             │                               │ [+] [输入问题、多行]               [发送] │
└─────────────┴───────────────────────────────┴───────────────────────────────────────────┘
```

**布局建议**（交给 Codex 按现有样式变量调整，非固定像素要求）：

- 在原导航和顶栏不变的前提下，编辑页主内容区以左右 `flex/grid` 分栏；表单区 `minmax(0,1fr)`，Agent 默认宽约 380–440px（大屏约占编辑内容区 30–36%），可收起；左右分隔线 1px。
- 编辑表单的最小有效宽度建议 620–680px，避免 Fluent 复杂选项被挤坏。
- 窗口过窄（例如不足约 1200px 可用总宽）时，右侧 Agent 改为**覆盖式抽屉 Drawer**，而不是让原表单水平溢出；用户主动展开/收起，关键 Fluent 表单始终可用。
- 收起时在编辑页面右边保留可见的窄入口（Agent 图标 + 未读/建议标识），不把 Agent 直接彻底移除导航。
- Agent 面板 `height: calc(100% - 已有顶栏高度)`，头部与底部输入区不参与消息列表滚动；长对话只滚动中间的消息区。
- 左侧原 Fluent 工作流步骤条横向溢出时仅在左侧区域内滚动；不要让右侧面板跟着横向滚动。

### 2.2 Agent 面板头部（从左至右）

| 部件 | 具体文案/样式 | 点击行为 |
|---|---|---|
| Agent 标识 | 小机器人图标 + `工程辅助 Agent` | 无需点击 |
| 当前模型 | 次级文字如 `当前模型：全局模型名称` | 只读；可点击跳转“设置”页相应区域，**不在模板独立切换模型** |
| 能力入口 | 小按钮/图标 `能力` | 小浮层只读展示：文丘里知识、计算工具和联网能力当前可用状态 |
| 折叠按钮 | `chevron-right` / `panel-right-close` | 收起 Agent，保留当前会话和运行状态；展开后恢复 |

头部状态标签可以是 `就绪 / 生成中 / 需要输入 / 服务异常`，不能仅凭前端打字动画表示真实后端状态。

### 2.3 空会话首次进入

会话首次进入（草稿创建后）展示短欢迎语与快捷问题：

> 我可以协助你分析边界层设置，比较 Uniform 和 Smooth Transition，并结合工程条件推荐参数。你想从哪里开始？

快捷问题：`了解两种方法`、`根据当前模型推荐`、`暂时不用`。

- **点击快捷问题等价于真实发送一条用户消息**，不能是无效装饰按钮；`暂时不用` 收起侧边栏。
- 首次引导与当前 `template_id/session_id` 关联，仅显示一次；已发生真实聊天时优先显示历史记录。
- 用户进入 **Add Boundary Layers** 设置**第一次**时，主动出现专业提示；由程序记录 `template_id + workflow_step_id` 的提示状态；不因为用户多次切换步骤重复刷消息。
- 如果此前用户主动收起 Agent，第一次进入该步骤时可在右侧入口出现“边界层设置建议”轻提示；不反复强制弹开。此前已经确认的“模板创建/设置完成后自动展开”情形保留，一次性处理。
- 非文丘里目录只显示通用工程师欢迎内容，不能展示未注册的专业工具能力。

### 2.4 消息区的内容组件（需要支持的不止文本）

1. `TextMessage`：AI 与用户的普通消息；长文本可展开、复制。
2. `AttachmentMessage`：用户上传图像的缩略图、文件名、上传状态及重新上传入口。图片识别仅在当前全局模型支持视觉时开放实际识别能力。
3. `DetectedInputsCard`：展示从文字或图片识别的关键参数，按 `已确认 / 待确认 / 缺失` 状态区分，来源可见。用户**通过聊天纠正**，工作区本身只读。
4. `MethodComparisonCard`：上下两张简短方法卡（右侧窄栏不强制双列），每张有适用性和按钮：`采用 Smooth Transition` / `采用 Uniform`。如果专业分析推荐一项，贴小型 `推荐` 标识并注明依据；用户始终可选另一项。
5. `ToolCallCard`：真实工具事件，如 `正在计算 Smooth 层数`、`已完成`、`失败`；展开查看**工具真实输入、单位、版本、执行结果**；不展示伪造的思考链。
6. `RecommendationCard`：方法、关键参数与单位、来源、映射状态、复制按钮、计算依据折叠区、后续验证项；如果真实 Fluent 字段尚未验证，明确写 `工程估算 · Fluent 字段待核验`。
7. `ErrorMessage`：模型连接/工具失败/缺参/文件解析失败，给用户可理解的下一步，不把失败结果伪装成成功。

**专业分析摘要**可以写“已知条件/采用假设/参考依据/工具实际计算/推荐与验证”，不能以“思考过程”名义暴露不可见的模型内部推理链。

### 2.5 底部消息输入区（建议贴近成熟桌面 AI App 形态）

```text
┌──────────────────────────────────────────────┐
│ 向工程辅助 Agent 提问，可描述模型和工况…       │
│                                              │
│ [+附件] [当前能力提示]               [发送 ↑] │
└──────────────────────────────────────────────┘
```

- 输入 `textarea` 默认 1–2 行，可随内容增长到约 5 行，再内部滚动；Enter 发送、Shift+Enter 换行（可与现有快捷键保持一致）。
- 左下角 `+` 菜单 V1 只包含**上传图片/附件**；未来其他能力可扩展，但不添加假的“生成工具”或“修改模板”选项。
- 上传前后检查格式、大小、接口能力；缩略图在输入区上方以可移除附件 chip 显示。模型不支持视觉时允许文字替代，不能声称解析成功。
- 右下角 `↑发送`；真实运行时变为 `停止`（需要服务端取消确认）；按钮禁用/启用与真实会话状态同步。
- 工具调用中的输入框可保留可读但阻止同会话并发新 Run，待本轮结束可继续发送；具体排队由现有框架能力判断。
- 用户手动滚到历史消息时，不自动拉回底部；只有接近底部才跟随新流式内容，必要时出现“跳至最新”按钮。

### 2.6 典型用户全过程（界面状态）

**状态 0：未配置全局模型**：Agent 历史可读，消息框显示 `请到设置 > AI 模型配置中完成连接`，有跳转按钮，Fluent 编辑器照常用。

**状态 1：首次欢迎**：静态欢迎卡及三个快捷问题。

**状态 2：用户选择“根据当前模型推荐”**：Agent 根据当前有的文字/附件列出已知信息和缺失信息；如还无工况，可引导上传结构图/截图或文字描述。只追问对当前判断有用的项。

**状态 3：方法比较**：显示 Uniform / Smooth 两张选择卡及推荐依据；点击一项是明确的用户选择，进入该方法的缺参检查。

**状态 4：方法分支**：Smooth 仅查 `first_yplus, target_outer_yplus, growth_rate`；Uniform 仅查 `density, dynamic_viscosity, characteristic_velocity, characteristic_diameter, target_first_yplus`；**不额外强制喉部速度/复杂区域树**。

**状态 5：参数明确但尚未完整**：AI 用一条短消息问当前最重要缺项，用户文字回答；图片提取的不确定值须确认，用户明确给出数值+单位的文本无需重复确认。

**状态 6：工具真实运行**：产生 `ToolCallCard`，展示真实开始/完成/错误事件。只有拿到后端结构化工具输出才展示完成数值。

**状态 7：推荐结果**：`RecommendationCard` 数值、单位、工具、来源、假设、可核验公式、Fluent 映射状态、验证项，支持复制；用户人工填写左侧表单。

**状态 8：改参数/换分支**：通过聊天修改特征直径等，旧结果依赖项标 `基于旧参数，需重新计算`；另一方法的计算历史不被覆盖。退出、重新进入恢复消息、计算卡和最新参数。

**状态 9：能力降级**：全局模型可聊天但不支持工具时可解释方法，但计算处明确提示 `当前模型不支持工具调用，无法完成可信的工具计算`；不阻断 Fluent 表单。

## 3. 页面 B：现有“设置”页底部的 AI 模型配置区

### 3.1 页面位置

左侧原 `设置` 导航 → 现有设置页**纵向滚动** → 一张新的白底卡片，标题 `AI 模型配置`，右侧小型 `全局统一` 标签。**不新增“模型管理”侧边栏入口，也不为拓展台配置第二套 API。**

### 3.2 具体表单布局

```text
┌── AI 模型配置 ─────────────────────────── [全局统一] ──┐
│ 所有工程辅助 Agent 与未来拓展台 Agent 使用此模型             │
│ 模型供应商        [OpenAI兼容接口           ▾]             │
│ 模型显示名称      [我的工程模型                ]             │
│ Model ID         [填写供应商提供的模型 ID     ]             │
│ Base URL         [https://...（按供应商）    ]             │
│ API Key          [••••••••••••••••] [显示/隐藏]             │
│ [▶ 高级设置：超时、温度、输出Token]                         │
│                                                           │
│ 连接状态 [未测试/已通过/连接失败]   [测试连接] [保存配置]  │
│ ── 能力检测 ────────────────────────────────────────────── │
│ 文本对话  [通过/失败/未测试]   工具调用 [通过/失败/未测试]     │
│ 图片理解  [通过/失败/未测试]   流式输出 [通过/失败/未测试]     │
│                                      [运行能力检测]         │
└───────────────────────────────────────────────────────────┘
```

推荐操作规则：先输入并保存配置，再单独**测试连接**；可以在保存时运行纯前端必要字段校验，网络测试需显式发起。能力检测单独按钮执行，显示实际结果与失败原因。按此前已确认的**方案 A**：即使工具或图像能力缺失，也允许模型生效，但对应 Agent 功能真实降级。

若现有项目已经实现多 Profile，则可在卡片内加 `选择当前模型/管理已保存配置`，**所有 Agent 仍只能使用同一个 active Profile**。如果现有项目只有单个配置，V1 无须为此引入新数据库和复杂列表界面。

API Key 仅掩码显示并保存在安全存储；不要让已保存的 Key 因用户未输入新值而被空字符串意外覆盖。页面跳转自 Agent 头部时，可滚动定位 `AI 模型配置` 卡片。

## 4. 数据到 UI 的映射（给 Codex 的技术契约）

| UI 部件 | 后端真实来源 | 不允许的行为 |
|---|---|---|
| 顶部当前模型名 | 全局 active ModelProfile | 每模板保存独立模型设置 |
| 首次提示 | 模板 ID + Fluent 步骤的持久化引导状态 | 每次进入步骤反复问候 |
| 参数摘要卡 | 当前会话已确认的工程参数 | 把图片猜测值无提示标为 confirmed |
| 方法比较 | Agent 专业依据与用户已知信息 | 把偏好 Smooth 写成绝对规则 |
| 工具卡 | 实际 `tool_call_id`、输入、状态、结果 | 仅生成文字“正在运行工具”而不执行 |
| 推荐数值 | 后端计算结果/输入快照 | 从 LLM 自由文字提取后当作唯一数据源 |
| Fluent 可填写标签 | 真实字段映射状态 | 未验证就声称字段确定可填 |
| 消息发送/停止 | Agno Run 的真实状态 | 前端卸载等于运行成功/取消 |
| 图片上传能力 | 全局模型实际能力测试与后端附件 API | 兼容接口就假定一定会看图 |

建议的逻辑组件名称（不是强制代码文件名）：`TemplateAgentPanel`, `AgentHeader`, `MessageList`, `WelcomeSuggestions`, `AttachmentPicker`, `EngineeringInputsSummary`, `MethodChoiceCard`, `ToolExecutionCard`, `ParameterRecommendationCard`, `AgentComposer`, `GlobalModelSettingsSection`。

优先复用项目已有 Input、Select、Card、Tabs、Toast、Dialog、Tooltip、Popover、ScrollArea/Drawer 等 UI 组件，不为了本模块新做完整设计系统。

## 5. 前端实现与接口检查顺序

1. **只读确认**当前模板编辑页布局、工作流步骤组件与现有状态管理方式，确保双栏后不会破坏 Fluent 表单。
2. 检查设置页原有表单和配置 API，确定“下方 AI 模型配置区”插入位置及凭据管理。
3. 确定 `template_id/session_id/step_id` 与右侧 Panel 的归属和恢复方式，先做静态结构与真实历史查询。
4. 实现文字聊天及首次/步骤引导；再接图片附件、当前能力状态。
5. 接入方法选择和已注册计算工具的真实调用记录；结果卡来自结构化工具输出。
6. 实际 Fluent 字段核验后展示可填写映射；未核验保留 `待验证`。
7. 完成小窗口/收起/长消息/断线/错误/切换模板测试，保存必要的用户界面状态。

## 6. 页面验收清单

- [ ] 页面仍是原 Fluent 模板编辑器，右侧附加 Agent，不重建整体工作流。
- [ ] 窄屏不会因为 Agent 导致 Fluent 表单水平崩坏。
- [ ] Agent 有头部、独立滚动消息区、固定底部输入区。
- [ ] `+` 真实可上传图片/附件，并有能力限制提示；按钮功能不是摆设。
- [ ] 首次欢迎/边界层步骤提醒只触发一次，快捷问题实际发送。
- [ ] 方法对比卡能选两条路径，不强制接受推荐。
- [ ] Smooth 三项输入 / Uniform 五项输入被正确识别；不强制喉部流速。
- [ ] 未知值确认、修改与旧结果失效能在 UI 可见。
- [ ] 工具调用卡显示真实执行事件，失败不伪造结果。
- [ ] 推荐卡显示数值、单位、来源、公式/假设和 Fluent 映射状态；复制按钮有效，左侧表单不被自动修改。
- [ ] 全局模型配置只在现有设置页底部，所有 Agent 读取统一 active 配置。
- [ ] 模型工具能力失败仍允许文字聊天但可靠降级。
- [ ] 切换模板/重进恢复各自消息和推荐卡，不串历史。

## 7. 给 Codex 的约束

**以现有截图/现有项目 UI 作为布局与视觉起点**，实现前先报告真实现有组件/页面位置及需要修改的文件。不要自行发明拓展台管理界面、多个模型 API 配置页、专门的喉部速度计算器、自动修改 Fluent 按钮或复杂参数表编辑器。涉及工作流字段和事件都要对照真实代码。上述尺寸为布局建议，若与现有实现冲突，应优先保持 Fluent 表单可用，并说明调整依据。

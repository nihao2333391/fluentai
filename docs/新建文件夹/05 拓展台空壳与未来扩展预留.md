# Fluent AI｜05 拓展台空壳与未来扩展预留

**版本：V0.1**

**状态：V1 范围已明确；具体界面与未来功能待后续细化**

## 1. 模块定位

拓展台是未来用于管理 Agent 专业能力的功能模块。

它将允许用户对零件目录中的工程知识、判断规则、Prompt 和计算工具进行可视化管理，并通过专门的拓展台 Agent 辅助建设专业能力。

**V1 仅实现拓展台页面空壳。**

当前版本不开展完整的拓展台功能开发。

## 2. V1 前端范围

### 2.1 导航入口

在现有 Electron 应用导航区域增加“拓展台”入口。

点击后进入拓展台占位页面。

入口的具体位置和图标应遵循现有导航风格。

### 2.2 占位页面

页面建议包含：

- 页面名称：拓展台。
- 简短功能介绍。
- 当前状态：功能规划中。
- 未来能力说明。

页面可以展示未来规划的四类能力：

工程知识、工程规则、Prompt 配置、计算工具。

这些内容在 V1 仅作为信息说明，不提供真实编辑功能。

### 2.3 交互边界

V1 不提供：

- 知识文件上传和管理。
- 工程规则编辑。
- Prompt 编辑。
- 工具创建与注册。
- 拓展台 Agent 对话。
- 工具代码生成和测试。
- 能力发布与版本管理界面。

避免设置看似可用但没有实现的操作按钮。

## 3. V1 后端范围

拓展台空壳本身不要求新增独立业务后端。

但是，02-D 模块需要提供现阶段工程辅助 Agent 正常运行所必需的能力管理基础。

包括：

- 零件目录对应的能力仓库。
- 工程知识和规则的基础存储与加载。
- 专业 Prompt 配置。
- 已有工具的注册与授权。
- 目录级能力继承。

**V1 使用开发配置导入模式。**

专业资料由 Codex 通过受控配置、脚本或后端服务导入。

这些基础服务归属于 Agent 能力仓库模块，而不是为了空壳额外建设一套拓展台服务。

## 4. 未来拓展台能力

未来规划支持：

### 工程知识管理

上传、整理、更新和检索专业文档。

### 工程规则管理

创建、修改和维护工程判断规则。

### Prompt 管理

管理不同目录的 Agent 专业提示词。

### 工具管理

查看、配置、授权、更新和停用计算工具。

### 拓展台 Agent

通过自然语言协助用户完成上述能力建设。

未来工具创建采用已确认的方案 B：

1. 用户描述工具需求或提供工程算法。
2. 拓展台 Agent 辅助生成代码、配置和测试用例。
3. 系统在隔离环境执行验证。
4. 用户审查结果并确认发布。
5. 受控服务注册正式工具。
6. 将工具授权给指定零件目录。
7. 所属模板 Agent 在后续调用中获得能力。

工具生成、隔离执行及受控发布属于未来版本，不在 V1 实现。

## 5. 与其他模块的关系

### 与模板库

未来拓展台直接使用模板库已经创建的零件目录，不建立另一套目录体系。

目录使用稳定的 category_id。

### 与工程辅助 Agent

工程辅助 Agent 消费已经发布、已经授权的专业能力。

它不能因为拓展台未来具备代码生成能力，就获得相同权限。

### 与 Agent 能力仓库

拓展台未来通过既有能力仓库服务管理资源。

知识资源、工程规则、Prompt 和工具注册使用统一标识、版本与授权机制。

### 与任务进程

拓展台不直接修改正在执行的 Fluent 网格任务。

能力仓库更新不应自动改变已经创建的任务配置快照及历史计算结果。

## 6. 未来扩展的技术约束

V1 应为能力资源保留稳定 ID、明确归属和必要的版本信息。

工具注册应具有独立的输入输出 Schema 和授权规则。

正式能力与草稿能力在未来需要有明确边界。

未来拓展台接入时，应扩展现有服务，而不是重新建设知识仓库、工具注册表或模板关系。

但 V1 不提前开发完整的草稿审批、沙箱执行、发布工作流或拓展台专属 Agent Runtime。

## 7. V1 验收标准

1. 应用导航存在拓展台入口。
2. 可以正常进入占位页面。
3. 占位页面明确展示当前功能规划状态。
4. 不存在虚假的可执行管理操作。
5. 拓展台未开发不影响模板库和工程辅助 Agent。
6. 已有专业能力能够通过 02-D 的开发配置导入方式使用。
7. 后续扩展可以复用零件目录 ID 和能力仓库基础服务。

**本模块 V1 只交付页面空壳及必要的架构兼容设计。正式功能在后续独立细化。**

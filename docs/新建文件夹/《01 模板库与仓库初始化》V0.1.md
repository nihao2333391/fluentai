## 一、模块目标

将原有“网格划分自动化”改造为“模板库”。

用户先创建零件类别目录，再在目录内创建、编辑、保存和应用网格划分模板。

每个零件目录对应一个后端共享能力仓库；每个模板关联独立工程辅助 Agent。

**核心目标：**

1. 支持不同零件类型的模板分类管理。
2. 让前端目录与后端仓库自动建立稳定关联。
3. 允许在专业能力尚未配置时直接创建模板。
4. 创建模板后自动建立草稿及独立 Agent 身份。
5. 实现模板设置、Agent 会话及历史数据的持久化。
6. 为未来拓展台管理能力仓库预留接口。

### V1 范围

第一版只需要实际完成一个文丘里管专业能力案例，但系统结构支持创建多个零件目录和多个模板。

## 二、用户操作流程

### 2.1 创建零件目录

用户进入模板库，点击“新建目录”。

界面出现目录创建弹窗，用户填写：

- 目录名称（必填）。
- 目录描述（选填）。

用户确认后：

1. 前端提交创建请求。
2. 后端分配稳定的目录 ID。
3. 创建目录数据库记录。
4. 初始化对应仓库结构及共享能力清单。
5. 系统设置该目录默认继承通用工程师能力。
6. 创建完成，前端显示新目录。

目录内可以暂时没有任何专业知识或工具。

### 2.2 在目录中创建模板

用户进入“文丘里管”目录，点击“新建模板”。

系统自动：

1. 创建模板草稿。
2. 关联当前零件目录。
3. 初始化 Fluent 工作流模板配置。
4. 建立模板专属 Agent 身份和默认会话关联。
5. 进入模板编辑页面。
6. 在右侧显示工程辅助 Agent 的欢迎信息与推荐问题。

即使用户尚未填写模板参数，草稿也可以保存。

### 2.3 编辑与自动保存

用户修改模板名称、工作流步骤或参数时，系统自动保存草稿。

建议提供三种状态反馈：

- 保存中。
- 已保存。
- 保存失败。

Agent 聊天记录独立保存，不要求每次对话都重新保存整个 Fluent 模板。

用户退出后重新进入，应恢复最后一次成功保存的模板设置和完整已持久化的 Agent 会话。

### 2.4 正式发布

用户完成设置后，点击“完成编辑”或原有保存操作。

后端根据 Fluent 工作流已有规则进行校验。

校验成功后，草稿成为可应用模板。

未通过校验时，页面定位存在问题的设置，并保留草稿。

### 2.5 应用模板

用户选择已发布模板和目标模型，创建独立的模板应用任务。

任务保存模板配置快照，随后交由任务进程模块管理。

## 三、前端页面要求

### 3.1 模板库主页面

采用上下分区：

**无任务时：**

模板库使用全部主内容区域。

**存在任务时：**

上方模板库占 65% 高度，下方任务进程占 35%。

任务进程为固定区域高度的独立滚动容器。

### 3.2 零件目录

V1 采用一级零件类别目录。

每个目录展示名称，进入后查看所属模板。

建议提供创建、重命名和删除入口。

目录删除规则需要考虑其下模板及历史任务引用，具体删除策略待确认。

### 3.3 模板列表

同一目录内展示草稿与已发布模板，并通过状态区不会分。

模板至少展示：

- 模板名称。
- 草稿 / 已发布状态。
- 最近修改时间。
- 编辑入口。
- 应用入口（仅已发布模板）。
- 删除操作。

### 3.4 模板编辑页面

保留现有 Fluent 工作流参数编辑结构。

右侧增加工程辅助 Agent 面板。

Agent 首次进入时展示欢迎介绍与快捷推荐问题；已有会话时恢复历史内容。

当前 V1 不要求 Agent 自动读取正在编辑的全部参数，也不要求它自动修改模板表单。

## 四、后端仓库初始化

### 4.1 仓库职责

零件目录创建后，后端应具有对应的独立工作空间。

建议逻辑结构：

```text
categories/
  category_<id>/
    manifest.json
    knowledge/
      documents/
      rules/
      prompts/
    capabilities.json
    templates/
      template_<id>/
        agent_config.json
        artifacts/
```

这仅为逻辑结构，正式目录位置需根据现有项目和 Electron 桌面应用的数据存储方式确定。

### 4.2 默认能力

新目录默认继承：

- 通用工程师角色。
- 联网搜索工具。
- 对话输出能力。
- 会话保存与恢复机制。

专业知识和计算工具为空时，不影响通用 Agent 使用。

### 4.3 目录与数据库一致性

数据库记录和文件仓库必须具有稳定的映射关系。

建议使用不可变的 `category_id` 作为存储标识。

修改目录展示名称时，不依赖物理文件夹改名。

初始化失败时应提供错误反馈与恢复机制，避免前端出现实际上无法使用的目录。

## 五、核心数据契约

**重要：以下为逻辑数据结构，不代表已经确认的实际数据库表名。**

### 5.1 PartCategory

| 字段               | 用途       |
| ---------------- | -------- |
| `id`             | 零件目录唯一标识 |
| `name`           | 目录展示名称   |
| `description`    | 目录描述     |
| `workspace_path` | 对应仓库位置   |
| `status`         | 初始化状态    |
| `created_at`     | 创建时间     |
| `updated_at`     | 修改时间     |

### 5.2 MeshTemplate

| 字段                    | 用途       |
| --------------------- | -------- |
| `id`                  | 模板唯一标识   |
| `category_id`         | 所属零件目录   |
| `name`                | 模板名称     |
| `status`              | 草稿、正式等状态 |
| `current_revision_id` | 当前模板版本   |
| `created_at`          | 创建时间     |
| `updated_at`          | 修改时间     |

### 5.3 TemplateRevision

保存某一版本的 Fluent 工作流配置。

关键字段：

- `revision_id`
- `template_id`
- `schema_version`
- `workflow_config`
- `revision_status`
- `created_at`

工作流参数优先复用现有项目的数据结构。

**在审查旧代码之前，不重新设计 Fluent 参数字段名称。**

### 5.4 TemplateAgent

每个模板关联独立的 Agent 身份。

关键字段：

- `agent_id`
- `template_id`
- `category_id`
- `config_ref`
- `default_session_id`

Agent 实际运行由平台统一 Agent Runtime 承担，无需为每个模板长期启动独立 Python 进程。

### 5.5 AgentSession

保存模板独立会话及消息引用。

会话的具体数据库结构优先复用 Agno 已有持久化机制。

模板服务只维护必要的关联，不重复实现完整聊天记录存储系统。

## 六、模块联动接口

### 模板库 → Agent

创建模板草稿后，建立 Agent 身份和会话关联。

打开模板时，根据模板 ID 加载对应 Agent。

### 模板库 → 能力仓库

目录共享专业能力由独立能力服务负责。

模板默认继承所属目录的已授权能力。

模板允许在授权范围内禁用或覆盖部分配置。

### 模板库 → 我的模型

模板创建或应用时，可选择原始模型进行参考或作为目标模型。

模型资源的实际文件管理由现有模型管理模块承担。

### 模板库 → 任务进程

应用模板时传递：

- 模板 ID。
- 模板配置版本 ID。
- 目标模型 ID。
- 当前执行所需的配置快照。

任务进程随后独立管理任务状态。

## 七、技术实现原则

### 7.1 参数表优先

在改造模板编辑器之前，Codex 必须先检查现有 Fluent 工作流参数结构。

应明确：

1. 工作流步骤如何定义。
2. 表单字段从哪里产生。
3. 参数如何校验。
4. 参数怎样保存。
5. 参数怎样转换为 Fluent/PyFluent 调用。
6. 未来 Agent 推荐值如何与字段 ID 对应。

若现有项目已经具备参数元数据，优先复用并补齐缺失信息。

### 7.2 Agent 与模板解耦

模板服务负责模板数据。

Agent Runtime 负责模型调用、会话和工具执行。

能力仓库负责知识与工具授权。

三者通过稳定 ID 和接口联动。

### 7.3 草稿数据可靠性

建议采用防抖自动保存、保存状态反馈、版本校验和失败重试。

页面关闭、重复提交及网络中断时，不能无提示地丢失未保存内容。

### 7.4 正式模板版本

建议已发布模板修改时创建新的草稿修订。

任务引用固定配置快照，避免历史任务受到模板更新影响。

具体修订实现方式需结合原有模板存储机制确认。

## 八、异常与边界处理

至少覆盖：

- 目录创建失败。
- 重名目录。
- 空目录。
- 模板草稿创建失败。
- 模板自动保存失败。
- 多窗口同时编辑同一模板。
- Agent 模型尚未配置。
- Agent API 调用失败。
- 目录专业知识为空。
- 模板正式发布校验失败。
- 已被任务引用的模板发生修改或删除。

错误反馈必须说明失败操作以及可以采取的恢复方式。

## 九、V1 验收标准

1. 用户可以从平台创建一个新零件目录。
2. 后端能够建立与该目录对应的仓库。
3. 用户可以在目录中创建多个模板。
4. 创建模板即形成可恢复的草稿。
5. 每个模板拥有独立 Agent 身份和会话。
6. 没有专业知识的目录仍能使用通用 Agent。
7. 用户退出并重新进入后，能够恢复已保存的模板参数和聊天历史。
8. 草稿通过校验后可以成为正式模板。
9. 正式模板可以选择模型并创建独立任务。
10. 修改模板不会自动更改已经创建的任务配置。

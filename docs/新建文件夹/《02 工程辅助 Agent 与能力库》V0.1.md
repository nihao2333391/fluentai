## 一、模块定位与职责

工程辅助 Agent 是用户在创建、编辑 Fluent 网格划分模板时使用的智能工程顾问。

它的核心工作是：

1. 理解用户的模型结构、研究目标和物理工况。
2. 主动引导用户提供工程分析所需的信息。
3. 检索已有工程知识、规则及相关资料。
4. 根据需要调用系统预先注册的计算工具。
5. 解释推荐依据，输出可供 Fluent 使用的参数建议。
6. 保留对话、计算过程和历史结果。

### 1.1 权限边界

V1 工程辅助 Agent 可以进行自然语言对话、联网搜索、专业知识检索和已授权工具调用。

Agent 不具备自行编写程序、动态注册工具、执行任意代码或直接修改模板表单的权限。

用户根据 Agent 的推荐结果，手动填写 Fluent 参数。

未来可以增加经用户确认的参数一键应用功能，但应由独立的前端操作实现。

## 二、Agent 前端交互

### 2.1 页面布局

工程辅助 Agent 位于模板创建或编辑页面右侧。

左侧保留现有 Fluent 工作流表单，右侧为独立的 Agent 对话面板。

对话面板应具备固定可用高度、内部滚动、消息输入、发送状态和历史消息恢复功能。

### 2.2 首次进入时主动引导

对于具备文丘里边界层专业能力的模板，Agent 首次进入时主动展示：

“在边界层设置中，Uniform 和 Smooth Transition 是两种可选方法。需要我介绍它们的区别，还是直接根据你的模型和工况进行推荐？”

下方提供可点击的快捷选项：

- 了解两种方法。
- 根据模型推荐方法。
- 暂时不需要。

用户点击选项后，直接发送对应消息并进入正常对话。

首次欢迎状态必须持久化。用户再次进入模板或刷新页面时，应恢复已有会话，不重复生成欢迎信息。

对于没有专业知识的目录，使用通用工程师欢迎内容。

### 2.3 对话交互要求

支持正常文字对话、快捷问题、工具调用状态展示、计算结果卡片及错误提示。

专业工程分析需要用户提供几何结构图片时，界面应提供图片附件入口；实际图像理解能力取决于所选模型是否支持多模态输入。

如果当前模型不支持图片输入，Agent 应说明限制，并引导用户使用文字填写必要参数。

长篇回复采用独立滚动区域。用户主动查看历史消息时，新增内容不能强制将页面拉到最底部。

### 2.4 推荐依据展示

用户希望理解 Agent 为什么推荐某一种方法。

因此，专业推荐结果需要清晰展示：

- 已识别的模型特征。
- 已知的工况参数。
- 当前研究目标。
- 采用的工程依据。
- 使用的公式与计算工具。
- 关键中间计算结果。
- 最终推荐。
- 假设、局限与待验证项目。

这里展示的是可核查的工程分析说明和工具计算记录，而不是模型内部未公开的原始思维过程。

## 三、模型配置

### 3.1 模型配置入口

建议在软件的统一设置区域提供模型配置入口，供各模板 Agent 使用。

配置内容包括：

| 字段 | 用途 |
|---|---|
| Provider | 模型服务提供商 |
| Model ID | 具体模型名称或标识 |
| Base URL | 模型服务接口地址 |
| API Key | 访问密钥 |
| Temperature 等参数 | 模型调用配置，按实际支持情况开放 |
| Capability Flags | 图片、工具调用、结构化输出等能力 |

用户可以配置多个模型连接，并指定默认模型。

模板 Agent 优先引用统一模型配置，避免每个模板重复填写 API Key。

是否允许单独指定模板默认模型，待结合现有模型配置功能进一步确定。

### 3.2 配置安全

API Key 应交由后端安全管理，不在前端持久化明文。

界面显示脱敏后的密钥信息。

应提供连接测试功能，区分密钥无效、接口不可达、模型不存在和功能不兼容等错误。

### 3.3 模型能力检查

不同模型可能支持不同的工具调用、图片输入及结构化输出能力。

系统应根据模型实际能力决定相关功能是否可用，而不是仅根据模型名称推断。

## 四、Agent 生命周期与会话管理

### 4.1 模板与 Agent 关联

每个模板拥有稳定的 Agent 身份和独立会话。

不同模板可以共享同一套 Agno 运行服务，但不得混用会话记录、模板配置或专属状态。

### 4.2 会话持久化

每轮对话至少关联：

| 数据 | 说明 |
|---|---|
| `template_id` | 对应模板 |
| `agent_id` | 对应 Agent |
| `session_id` | 对话会话 |
| `run_id` | 本轮模型执行 |
| 消息内容 | 用户与 Agent 的交互 |
| 工具记录 | 调用参数及结果 |
| 时间信息 | 创建、更新及执行时间 |

优先复用 Agno 提供的会话存储机制。

### 4.3 页面切换与恢复

用户离开模板编辑页面时，已保存的对话和结果保留。

再次打开模板时，恢复原有会话。

对于仍在生成中的回答，需要由后端维护运行状态，前端重新进入时应查询运行结果或明确显示中断情况。

### 4.4 长对话与上下文管理

保存完整历史与向模型发送完整历史是不同的事情。

系统应保留原始消息，但允许根据模型上下文限制选择历史消息或使用摘要。

当估算上下文接近模型限制时，应在当前回复结束后提供提示。

摘要不能覆盖原始工程参数、工具输入输出及已确认的计算结果。

## 五、能力继承与加载

### 5.1 能力来源

Agent 的有效配置由三个层级组成：

1. 平台通用能力。
2. 所属零件目录的专业能力。
3. 模板专属配置。

目录能力更新后，模板 Agent 下一轮调用默认继承新版本。

模板可以禁用授权范围内的部分能力，但不能自行获得未授权的工具。

### 5.2 能力分类

| 能力 | 加载方式 |
|---|---|
| 平台通用 Prompt | Agent 初始化时组合 |
| 目录专业 Prompt | 按目录配置组合 |
| 工程规则 | 根据规则类型及适用范围加载 |
| 专业知识 | 通过检索服务按需获取 |
| 已注册计算工具 | 根据有效授权清单加载 |
| 联网搜索 | 由平台统一配置 |

专业知识文档只是可引用的信息来源，不能自行扩大 Agent 的工具权限。

### 5.3 当前能力查看

在 Agent 面板中提供只读的“当前能力”入口。

用户能够查看当前模型、联网搜索状态、可用知识和计算工具。

V1 暂不通过该入口修改能力，未来由拓展台负责配置。

## 六、文丘里边界层工程辅助工作流

### 6.1 业务目标

以已有冷热混合文丘里模型为专业案例。

Agent 帮助用户选择 Uniform 或 Smooth Transition，并针对选定的方法输出推荐参数。

### 6.2 工程信息采集

Agent 根据已有信息判断是否还需要：

- 模型结构与关键尺寸。
- 入口、喉部及相关局部口径。
- 流体物性参数。
- 入口速度、流量及边界条件。
- 湍流模型。
- 目标壁面分辨率及目标 y+。
- 研究目的与重点分析区域。

参数不充分时，Agent 应主动询问，而不是自行假设某个固定模型尺寸。

### 6.3 推荐方法

Agent 首先识别模型和工况，再给出两种方法的比较与推荐。

推荐结论应包含工程依据、适用条件和不确定性。

用户可以选择推荐的方法，也可以选择另一种方法继续计算。

### 6.4 Smooth Transition 分支

优先复用已有层数推荐算法。

根据已有的 y+ 目标、首层 y+、增长率等参数进行计算，输出与 Fluent 参数表对应的层数推荐及相关说明。

具体参数名称、计算式和数值范围以既有封装文档及核实后的 Fluent 字段定义为准。

### 6.5 Uniform 分支

优先复用已有首层高度计算工具。

需要结合当前模型的有效口径或水力直径、速度、流体密度、动力黏度及目标 y+ 等信息进行计算。

不同文丘里模型的口径可能不同，首层高度必须按当前模型重新计算。

对于侧向流入、混合区或局部壁面剪切难以用简化公式准确预测的情况，应明确说明计算假设和适用范围。

### 6.6 结果展示

推荐结果至少提供：

- 所选方法。
- 推荐填写参数。
- 参数数值与单位。
- 计算依据。
- 关键中间结果。
- Fluent 对应字段。
- 工程假设和待验证项。

用户在 V1 手动填写这些参数。

## 七、Fluent 参数 Schema 联动

Agent 推荐参数必须与真实的 Fluent 工作流表单建立字段映射。

建议建立统一的参数元数据，包含：

| 字段 | 说明 |
|---|---|
| `parameter_id` | 系统内部稳定字段标识 |
| `workflow_step_id` | 所属工作流步骤 |
| `fluent_field` | Fluent 实际字段映射 |
| `method` | Uniform 或 Smooth Transition |
| `data_type` | 参数类型 |
| `unit` | 计算及显示单位 |
| `validation` | 校验规则 |
| `source` | 用户输入或计算工具 |
| `schema_version` | 参数定义版本 |

**必须先完成参数表设计和真实字段核对，再开发 Agent 推荐结果与前端表单的对应逻辑。**

同一参数不应分别由 Agent、前端和 Fluent 执行服务维护三套互不关联的定义。

## 八、异常处理

至少覆盖：

- 模型服务连接失败。
- API Key 错误。
- 当前模型不支持工具调用。
- 图片输入不受支持。
- 缺少工程计算参数。
- 工具输入校验失败。
- 工具计算异常。
- 专业知识检索没有结果。
- 模型返回无效的参数结构。
- 用户离开页面或中断生成。
- 会话恢复失败。

工程计算工具出错时，不得将未经过计算的数值伪装为工具结果。

## 九、Codex 技术审查要求

正式实施之前，应先检查：

1. 是否已有模型 API 配置与调用封装。
2. 现有前端是否具备可复用的对话组件。
3. Agno 与当前 FastAPI 架构如何集成。
4. 现有模板配置及参数表如何与 Agent 结果关联。
5. 边界层计算脚本是否可以直接复用。
6. 当前后端数据库是否适合保存 Agent 会话。
7. 是否已经有可复用的联网搜索服务。
8. 各模型对工具调用、图片输入及结构化输出的实际支持情况。

---

## 十、V1 验收目标

1. 创建模板后可以打开对应的独立 Agent。
2. 首次进入展示欢迎引导，之后恢复对话。
3. 通用目录在没有专业知识时正常对话。
4. 文丘里目录能够使用专业知识和已注册计算工具。
5. Agent 能够主动收集缺失工程信息。
6. 用户可以分别选择 Uniform 和 Smooth Transition 分支。
7. 计算结果具有明确的依据、单位和来源。
8. 推荐参数可以对应 Fluent 表单的真实字段。
9. 会话在页面切换和软件重新打开后仍可恢复。
10. Agent 不直接修改模板表单或创建新工具。

**审查范围：00、01、02-A～02-D、03、04、05、06、06-A、06-B**

**版本：V0.1**

**审查依据：此前已确认的业务决定及现有需求文档**

**审查边界：本次仅进行文档一致性审查，尚未审查实际项目代码。**

## 一、总体审查结论

当前各模块的业务定位整体一致：

- 模板库负责零件目录与模板。
- 工程辅助 Agent 负责对话、工程分析及参数推荐。
- 能力仓库负责共享知识、规则、Prompt 与工具。
- 我的模型负责原始几何模型资源。
- 任务进程负责 Fluent 任务状态及下一步操作提醒。
- 拓展台 V1 仅提供占位页面。

各模块之间不存在需要推倒重来的重大架构冲突。

但需要修订部分重复定义，收敛 V1 的技术复杂度，并将尚未验证的技术假设明确标记。

## 二、需要修订的六项问题

### 问题 1：全局模型配置存在旧方案残留

**涉及文档：02、02-A、06。**

早期曾设计过模板独立覆盖模型的方案，后来已经明确选择全局统一模型。

**最终统一要求：**

系统可以保存多个模型配置，但同一时间只有一个全局生效模型。

所有模板工程辅助 Agent 默认使用它。

每个模板保留独立的会话、工程参数和专业能力。

模板内部不提供独立模型选择器。

需要将旧文档中的模板模型绑定、模板独立覆盖等表述移除或标记为被 V0.2 替代。

### 问题 2：任务进度条的颗粒度不统一

**涉及文档：03、06、06-B。**

早期采用四阶段进度条，后续明确用户最关心的是两个主要操作节点：

1. 可以生成面网格。
2. 可以生成体网格。

**推荐统一方式：**

前端以面网格和体网格两个主要节点展示进展。

每个节点可显示准备中、待操作、生成中、已完成等状态。

后端按照现有 Fluent 工作流记录实际事件，不强制只保留两个或四个内部状态。

这样既满足用户的主要需求，也避免为四格进度条重新设计不必要的 Fluent 状态系统。

### 问题 3：Uniform First Height 的字段映射尚未验证

**涉及文档：02-B、06、06-A。**

工程算法可以计算首层高度，但不能直接证明当前 Fluent Meshing 工作流具有对应且可填写的参数字段。

**统一要求：**

先保留既有 First Height 计算算法。

Codex 必须检查真实 Fluent 2025 R2 工作流类型、参数面板、现有前端字段及 PyFluent API。

计算结果经过映射验证后，才能标记为 Fluent 可直接填写参数。

未经验证时，标记为工程估算结果。

Smooth Transition 的 Transition Ratio 等参考值同样遵循此规则。

### 问题 4：Agent 能力仓库的 V1 范围偏大

**涉及文档：02-D、05、06。**

现有草案提到了完整版本管理、混合检索、通用规则系统、工具生命周期等较复杂设计。

这些适合作为长期架构目标，但 V1 不需要全部实现。

**统一要求：**

V1 优先完成：

- 目录能力的基础存储与加载。
- 文丘里专业知识导入与检索。
- 专业 Prompt 配置。
- 已有 Python 计算工具注册及授权。
- Agent 按目录继承能力。
- 基本工具版本和调用记录。

V1 采用已确认的开发配置导入方案 A。

完整可视化管理、生成工具沙箱、复杂审批和发布工作流留给未来拓展台。

### 问题 5：Agent 工程参数管理不应过度复杂

**涉及文档：02-C、06-A。**

已经确认采用方案 A：通过聊天提供参数，工作区只读展示，并允许轻量确认。

因此 V1 不需要开发复杂的工程数据管理器。

**统一要求：**

每个模板主会话至少维护一份当前有效的工程参数集合。

支持参数确认、更新、单位校验、计算快照和旧结果失效标记。

保留历史计算结果。

完整多案例管理、参数表直接编辑、跨模板案例共享属于后续扩展。

工程参数工作区只管理 Agent 分析数据，不能自动修改 Fluent 表单。

### 问题 6：任务删除需要保留文件索引

**涉及文档：03、04、06-B。**

任务删除已经确认采用方案 C：

默认保留网格文件和日志，允许勾选一并清理。

但仅从任务列表移除记录、保留文件还不够。

**统一要求：**

默认删除时采用逻辑删除或等效机制，保留必要的文件归属及存储引用。

清理操作只针对任务专属文件。

原始模型、模板、共享资源及其他任务产物必须受到保护。

已完成任务在用户手动删除前始终保留在任务列表。

## 三、跨模块数据责任检查

| 数据 | 唯一主要管理方 | 其他模块使用方式 |
|---|---|---|
| 零件目录 | 模板库服务 | 使用 category_id 引用 |
| 模板配置 | 模板服务 | Agent 只读取必要上下文 |
| 全局模型配置 | 模型配置服务 | Agent 在每轮请求时解析 |
| Agent 会话 | Agent 服务 | 通过 session_id 恢复 |
| 工程输入 | 工程参数服务 | 工具通过校验后的快照读取 |
| 工程知识 | 能力仓库 | Agent 按授权检索 |
| 计算工具 | 工具注册与执行服务 | Agent 按授权调用 |
| 原始几何模型 | 我的模型 | 任务通过 model_id 引用 |
| 网格执行任务 | 任务服务 | 工作流与前端读取 |
| Fluent 实际操作 | Fluent 执行服务 | 向任务服务报告真实状态 |
| 任务产物 | 任务资源服务 | 通过 task_id 关联 |

**检查结论：**

数据责任基本清楚。

建议最终文档明确数据库记录、文件仓库和 Agent Runtime 的实际数据归属，避免出现多个模块直接修改相同文件的情况。

## 四、必须保留的技术验证事项

下列事项不能仅通过需求文档推断，需要 Codex 审查真实代码。

| 验证项目 | 需要确认什么 |
|---|---|
| Fluent 参数 | 实际字段、单位、方法适用条件、PyFluent 映射 |
| 面网格就绪事件 | 原有生成按钮为什么出现和启用 |
| 后台执行 | 切换页面后 Fluent 操作是否继续 |
| 多任务 | 现有 Fluent 会话是否支持多任务交替或并行 |
| 模板存储 | 现有模板数据结构能否扩展草稿及版本 |
| Agent 集成 | Agno 与当前 FastAPI 的兼容方式 |
| 会话存储 | 如何复用现有数据库或 Agno 存储 |
| 模型配置 | API Key 当前如何存储及调用 |
| 文件资源 | 原始模型、网格产物和日志的实际位置 |
| 历史数据 | 原有模板和任务如何兼容新结构 |

其中，“页面切换后任务能否继续推进到待操作状态”是任务进程模块最重要的技术验证项。

如果现有系统完全依赖前端页面维持工作流，Codex 就需要提出最小后端改造方案。

## 五、V1 技术复杂度控制

建议把系统划分为三类。

### A. V1 必须完成

- 模板库与目录仓库。
- 模板草稿保存及发布。
- 全局 AI 模型配置。
- 模板独立 Agent 与会话。
- 通用对话和联网搜索。
- 文丘里专业知识与已有工具。
- 工程输入及参数推荐。
- Fluent 参数映射。
- 多任务操作就绪提醒。
- 任务查看、保留与删除。
- 拓展台空壳。

### B. 仅保留基础兼容设计

- 模板和工具版本关联。
- 资源存储与授权接口。
- 历史工具调用追溯。
- 任务状态持久化。
- 基本异常记录。
- 未来拓展台的能力管理入口预留。

### C. 暂不进入 V1

- 拓展台 Agent 的实际运行。
- AI 自动生成并注册工具。
- 生成代码隔离沙箱。
- 完整的专业规则编辑系统。
- 工程参数双向编辑器。
- Agent 自动填写 Fluent 模板。
- 复杂的多案例管理界面。
- Fluent 计算百分比预测。
- 完整断点恢复与任务失败自动重试。

## 六、尚未决定的业务规则

以下内容在之前讨论中尚未正式确认。

1. 目录删除时如何处理所属模板。
2. 已发布模板修改后的具体发布交互。
3. 草稿多窗口同时编辑的冲突策略。
4. 原有模板的数据迁移方案。
5. 被任务引用的原始模型如何删除。
6. 运行中的任务是否允许直接删除及如何处理执行进程。
7. 任务失败后的重试与恢复机制。

其中第 7 项已经明确要求暂时搁置，不应在 Codex 开发时擅自添加复杂恢复功能。

其余事项可以在最终交接文件中列为待决策问题；其中纯技术部分先由 Codex 检查现有实现并提供建议。

## 七、统一文档的优先级规则

为避免旧方案影响实际开发，建议采用以下顺序：

1. 用户明确确认的最新业务决定。
2. 系统级整合文档中已经核实的一致性规则。
3. 对应模块最新的详细需求。
4. 较早的技术设计草案。
5. 尚未核实的技术示例。

但所有涉及实际 Fluent 参数、软件版本、API 能力和现有代码行为的判断，都必须以技术验证结果为依据。

发现需求与代码存在冲突时，应向用户报告并提出方案，而不是直接修改业务需求。

---

## 八、系统集成验收主线

最终交付应能完成：

创建零件目录 → 自动初始化能力空间 → 创建模板草稿 → 使用 Agent 辅助分析 → 保存 Fluent 参数 → 发布模板 → 选择原始模型 → 创建任务 → 等待模型导入 → 任务卡片提示可生成面网格 → 返回任务执行生成 → 完成体网格 → 保留任务与网格结果。

此外，需要单独验证：

- 不同模板 Agent 会话隔离。
- 全局模型切换不丢失历史记录。
- 专业工具授权有效。
- 参数改变后旧推荐可追溯。
- 一个原始模型可以创建多个独立任务。
- 任务删除默认保留网格产物及日志。

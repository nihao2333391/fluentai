# Fluent AI｜06-B 跨模块实体关系、接口与状态机统一设计

**文档版本：V0.1**  
**文档状态：系统级技术设计草案，待全局代码审查**  
**关联文档：00—06-A**

## 一、设计目标

统一模板库、工程辅助 Agent、能力仓库、我的模型、任务进程和 Fluent 执行服务之间的交互方式。

本文件负责确定：

1. 核心业务实体及其归属。
2. 模块之间的调用关系。
3. 数据的创建、更新、查询与删除职责。
4. 模板、Agent 和任务的生命周期。
5. 跨模块状态更新与异常处理。
6. 前后端接口必须遵守的数据契约。

所有实体和接口名称均为建议命名。正式实现优先复用现有项目结构。

## 二、核心实体关系

### 2.1 实体关系总表

| 实体 | 归属模块 | 主要关联 | 生命周期 |
|---|---|---|---|
| PartCategory | 模板库 | 多个模板、共享能力 | 创建、重命名、删除 |
| MeshTemplate | 模板库 | 所属目录、Agent 身份 | 草稿、发布、归档 |
| TemplateRevision | 模板库 | 对应模板、Fluent 配置 | 草稿修订、正式版本 |
| TemplateAgent | Agent 服务 | 对应模板、目录能力 | 初始化、运行、停用 |
| AgentSession | Agent 服务 | Agent、消息、运行记录 | 创建、恢复、继续 |
| EngineeringCase | 工程参数服务 | 会话、工程输入 | 创建、更新、保存 |
| EngineeringRecommendation | 推荐服务 | 输入快照、计算工具 | 生成、过期、追溯 |
| CapabilityResource | 能力仓库 | 目录、版本 | 导入、启用、更新 |
| RegisteredTool | 工具注册服务 | 版本、授权 | 注册、启用、停用 |
| ModelAsset | 我的模型 | 原始几何文件 | 导入、引用、删除 |
| MeshingTask | 任务服务 | 模板版本、模型、产物 | 创建、执行、完成、删除 |
| TaskArtifact | 任务服务 | 任务、网格文件和日志 | 生成、保留、清理 |

### 2.2 必须遵循的关联规则

- 一个零件目录拥有多个模板。
- 每个模板拥有独立 Agent 身份。
- 每个模板 V1 默认具有一个主会话。
- 同目录模板继承相同的有效专业能力。
- 不同模板的会话和工程参数相互隔离。
- 一个已发布模板可以创建多个执行任务。
- 一个原始模型可以被多个模板重复应用。
- 一个任务绑定创建时的模板配置快照。
- 一个任务拥有自己的执行状态和生成产物。

模板名称、目录名称和原始文件名都属于展示信息，实际关联使用稳定 ID。

## 三、系统服务职责

建议按照业务责任区分服务。

| 服务 | 核心责任 | 不承担的责任 |
|---|---|---|
| CategoryService | 零件目录管理 | 执行专业计算 |
| TemplateService | 模板草稿、版本、发布 | 运行 Agent |
| AgentService | Agent 身份、会话、运行 | 修改 Fluent 表单 |
| ModelConfigService | 全局模型连接与选择 | 模板独立模型覆盖 |
| CapabilityService | 知识、规则、Prompt 和授权 | 任意执行生成代码 |
| EngineeringCaseService | 工程输入及版本 | 修改 CAD 文件 |
| ToolExecutionService | 已注册工具执行 | 动态生成工具 |
| ModelAssetService | 原始模型资源 | 管理网格计算结果 |
| MeshingTaskService | 任务记录、状态、产物引用 | 替代 Fluent 执行引擎 |
| FluentExecutionService | Fluent/PyFluent 实际工作流 | 管理模板与 Agent 会话 |

这些是逻辑服务职责，不要求在代码中为每项职责分别创建进程或微服务。

V1 优先使用现有 FastAPI 服务进行模块化扩展。

## 四、链路 A：创建目录与模板

### 4.1 创建零件目录

用户在模板库中创建目录。

建议后端流程：

1. 接收目录名称及描述。
2. 校验名称和请求。
3. 分配 category_id。
4. 创建目录数据库记录。
5. 初始化共享能力空间。
6. 配置平台默认通用 Agent 能力继承。
7. 返回目录创建结果。

仓库初始化需要考虑重复请求和中途失败。

数据库成功、文件初始化失败时，应有补偿或重试机制。

不能向前端返回已经可以正常使用、但实际仓库尚未初始化完成的目录。

### 4.2 创建模板草稿

用户进入目录后点击新建模板。

建议使用后端协调流程：

1. TemplateService 创建草稿。
2. 建立 template_id 与 category_id 关联。
3. 初始化现有 Fluent 工作流配置。
4. AgentService 建立独立 Agent 身份。
5. 建立默认主会话关联。
6. 保存模板与 Agent 的关系。
7. 返回模板编辑页面所需的初始化数据。

初始化过程中需要保证重复请求不会创建多个无关 Agent。

推荐由稳定模板 ID 进行幂等处理。

### 4.3 编辑与自动保存

用户编辑 Fluent 参数时，TemplateService 保存草稿修订。

Agent 会话单独保存。

两个保存流程独立运行，不要求聊天消息触发模板参数保存。

自动保存应具有版本号，处理重复提交及过期写入。

## 五、链路 B：Agent 初始化与专业能力加载

### 5.1 初始化

用户进入模板编辑页面后：

1. 查询 template_id 对应的 Agent。
2. 获取默认主会话。
3. 获取全局当前模型配置。
4. 获取目录有效能力清单。
5. 加载平台 Prompt、目录 Prompt 和模板配置。
6. 恢复历史消息。
7. 展示首次欢迎或历史会话。

首次欢迎内容可以由预设配置生成，不必立即调用模型 API。

### 5.2 发起对话

每次用户发送消息，AgentService：

1. 校验 template_id、agent_id、session_id 的关联。
2. 获取当前全局模型。
3. 获取当前生效的能力与工具授权。
4. 读取必要的工程参数工作区。
5. 创建 run_id。
6. 固定本轮模型和能力版本。
7. 执行 Agent 并输出流式结果。
8. 保存消息、工具调用及最终状态。

不同模板的 Agent 会话之间不得发生数据串用。

### 5.3 工具调用

Agent 发起专业计算请求时：

1. ToolExecutionService 校验工具 ID。
2. 检查当前目录授权。
3. 读取工具 input_schema。
4. 检查必要工程参数。
5. 创建计算输入快照。
6. 调用已有 Python 函数。
7. 验证 output_schema。
8. 保存工具调用结果。
9. 返回 Agent 生成工程解释。

权限校验必须在后端完成，不能仅依靠 Prompt 限制。

## 六、链路 C：应用模板与 Fluent 任务

### 6.1 创建任务

用户选择已发布模板和原始模型。

后端执行：

1. 校验模板发布状态。
2. 获取固定模板版本及配置。
3. 验证目标模型资源有效。
4. 创建 task_id。
5. 保存模板配置快照和原始模型引用。
6. 初始化任务工作空间。
7. 准备 Fluent 工作流执行。
8. 返回任务创建结果。

此时任务由任务服务负责管理，不继续依赖模板编辑器的页面生命周期。

### 6.2 Fluent 工作流推进

FluentExecutionService 负责执行实际操作。

MeshingTaskService 根据真实执行事件更新任务状态。

重点事件包括：

- 模型导入开始。
- 模型导入完成。
- 面网格操作已就绪。
- 面网格生成开始。
- 面网格生成完成。
- 体网格操作已就绪。
- 体网格生成开始。
- 体网格生成完成。
- Fluent 执行失败或中断。

任务卡片与工作流页面通过相同状态来源更新显示。

### 6.3 待操作提醒

当后端确认生成操作已满足前置条件时：

- 更新 next_action。
- 将任务标记为待用户操作。
- 通知前端刷新。
- 在任务列表中突出显示并优先排序。

点击任务卡片，返回对应工作流并定位操作位置。

用户仅查看任务时，不清除提醒。

确认执行相应操作后，才将状态更新为运行中。

### 6.4 多任务隔离

每个任务必须具有独立的数据库记录、配置快照和文件归属。

Fluent 实际执行能力是否支持多个同时运行的会话，需要由 Codex 核查现有架构、计算资源和进程管理方式。

V1 不能默认多个 Fluent 任务必然同时计算。

即使 Fluent 执行端需要排队，任务管理层仍可保留多个独立任务。

## 七、任务与文件的生命周期

### 7.1 任务完成

体网格生成成功后，将任务状态更新为 completed。

任务继续显示在任务进程列表中。

相关面网格、体网格及日志按照任务归属保存。

### 7.2 删除任务

用户点击删除后弹出确认框。

默认仅移除任务记录，保留网格文件和日志。

用户可以勾选清理该任务生成的文件与日志。

系统必须保护：

- 原始 CAD 模型。
- 模板及其版本。
- 共享能力资源。
- 其他任务引用的文件。

对于保留文件的删除操作，需保留可追溯的产物索引或清理记录，避免文件成为无法查找的孤立数据。

### 7.3 执行失败

任务失败后保留已有日志及有效产物。

失败后的重试、断点恢复及重新创建策略暂不确定。

V1 技术设计至少需要能识别失败并防止将其误判为完成。

## 八、主要状态机设计

### 8.1 模板状态

建议状态：

- draft：草稿。
- published：已发布。
- archived：归档。

草稿可以编辑、自动保存和恢复。

已发布模板可应用于模型。

已发布模板的后续编辑应产生可追溯修订，具体交互待确认。

### 8.2 Agent Run 状态

建议状态：

- queued
- running
- tool_running
- completed
- failed
- cancel_requested
- cancelled
- interrupted

所有运行状态都必须关联 run_id。

前端只负责显示后端确认的状态。

### 8.3 任务状态

建议将工作流位置与执行状态分开保存。

工作流位置：

- preparing_geometry
- surface_settings
- surface_generation
- volume_settings
- volume_generation
- finished

执行状态：

- pending
- processing
- action_required
- running
- completed
- failed
- interrupted

例如：

工作流位置 = surface_settings

执行状态 = action_required

下一操作 = generate_surface_mesh

表示模型已经准备好，用户可以进入生成面网格操作。

### 8.4 状态转换原则

每次状态转换应记录来源事件和发生时间。

只有满足前置条件时才能推进状态。

重复事件应进行去重或幂等处理。

过期事件不能覆盖更新后的有效状态。

对需要恢复的任务，应先检查真实执行状态，再决定前端展示什么。

## 九、统一接口契约

以下为逻辑接口，实际 API 路径待代码审查后确定。

| 接口组 | 操作 | 主要业务对象 |
|---|---|---|
| Categories | 创建、查询、更新目录 | PartCategory |
| Templates | 创建草稿、保存、发布、查询 | MeshTemplate |
| Agent | 获取 Agent、读取会话、运行消息 | TemplateAgent、AgentSession |
| Model Config | 设置及获取全局模型 | ModelProfile |
| Capabilities | 读取目录有效能力 | CapabilityResource |
| Engineering Cases | 更新工程输入、查询当前参数 | EngineeringCase |
| Tools | 调用已授权工具 | RegisteredTool |
| Models | 导入、查询、引用原始模型 | ModelAsset |
| Meshing Tasks | 创建任务、查询状态、删除 | MeshingTask |
| Fluent Events | 更新任务执行状态 | TaskEvent |

### 9.1 通用接口要求

每个写入接口都应定义：

- 请求唯一标识或幂等策略。
- 操作对象 ID。
- 数据校验规则。
- 成功结果。
- 错误编码。
- 数据版本或并发控制要求。

异步执行接口还需要返回对应 run_id 或 task_id。

### 9.2 权限与边界

工程辅助 Agent 不具有模板修改、代码生成或工具注册权限。

工具调用只允许使用已注册且当前授权有效的工具。

未来拓展台 Agent 的工具创建权限通过独立的受控流程实现。

## 十、跨模块异常处理

必须考虑：

1. 目录创建完成但仓库初始化失败。
2. 模板草稿创建后 Agent 初始化失败。
3. 模板保存与 Agent 消息保存先后失败。
4. 全局模型配置发生变化。
5. 模型服务连接中断。
6. 工具授权或版本发生变化。
7. 工程输入更新导致旧计算结果失效。
8. 模型资源被其他任务引用。
9. Fluent 执行服务中断。
10. 前端页面切换或软件重新打开。
11. 重复创建任务。
12. 文件清理部分失败。

需要通过稳定 ID、明确业务所有权、状态记录及异常补偿机制处理这些情况。

## 十一、优先开发依赖关系

建议按照基础能力依赖顺序组织开发：

**第一组：业务数据基础**

目录、模板、模型资源引用、统一参数 Schema。

**第二组：Agent 基础服务**

全局模型配置、Agent 身份、会话持久化、通用对话。

**第三组：专业能力服务**

能力仓库、专业文档、规则、工具注册、工程参数工作区。

**第四组：业务联动**

Agent 参数推荐与 Fluent 字段映射、模板应用任务、任务提醒。

**第五组：集成与完善**

异常恢复、数据迁移、日志、UI 状态一致性、整体测试。

实际实施顺序需根据现有代码可复用程度调整，不强制重构已经稳定工作的模块。

## 十三、V1 验收标准

1. 创建目录能够初始化共享能力空间。
2. 创建模板能够建立独立 Agent 关联。
3. 全局模型切换不破坏会话隔离。
4. 专业工具只能在授权范围内调用。
5. 工程参数能够结构化保存和追溯。
6. 模板应用形成独立任务及配置快照。
7. 一个模型可以被多个模板重复应用。
8. 任务状态由真实工作流事件驱动。
9. 可生成面网格时给出明显的操作提醒。
10. 任务完成后保留，并支持用户手动删除。
11. 删除任务默认保留网格文件和日志。
12. 已有模板、原始模型与任务结果的数据归属清晰。
13. 各模块不存在重复维护的核心状态来源。

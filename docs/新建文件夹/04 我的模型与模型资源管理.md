
# Fluent AI｜04 我的模型与模型资源管理

**版本：V0.1**

**状态：初步需求规格**

## 1. 模块目标

我的模型是平台的原始模型资源管理入口。

用户从外部导入模型文件，平台负责保存、展示和管理模型资源，并在应用模板时提供模型选择。

本模块不负责网格划分、几何编辑、边界层设置或仿真计算。

## 2. 核心功能

### 2.1 模型导入

支持用户从本地选择模型文件并导入平台。

具体支持格式沿用现有项目的文件导入能力，后续通过代码审查核对。

导入成功后：

1. 后端接收模型文件。
2. 检查文件类型及必要的完整性。
3. 保存原始文件。
4. 创建模型资源记录。
5. 返回模型唯一标识。
6. 前端刷新模型列表。

导入失败时，显示明确原因，不生成可正常使用的虚假模型记录。

### 2.2 模型列表

展示已经导入的模型。

建议保留以下信息：

- 模型名称。
- 原始文件名称。
- 文件格式。
- 文件大小。
- 导入时间。
- 当前资源状态。

用户可以选择模型，进入现有模型详情或相关操作页面。

不额外开发复杂的模型管理功能。

### 2.3 模型资源存储

原始模型文件由后端统一管理。

数据库保存资源元数据及文件存储引用。

建议使用稳定的 model_id 作为模型标识，不直接依赖文件名称作为关联依据。

模型原始文件与任务生成的网格文件分开管理。

### 2.4 模型删除

删除模型资源时，需要检查其是否被现有任务引用。

对于已经被历史任务引用的模型，优先采用软删除或隐藏方式，保留历史任务所需的文件引用。

具体删除确认交互待结合现有功能进一步确定。

## 3. 与模板库的关系

用户在应用模板时，可以从我的模型中选择目标模型。

模板库不直接拥有原始模型文件，只保存应用时的模型资源引用。

模板应用时，系统读取：

- model_id
- 原始文件引用
- 文件名称
- 必要的模型元数据

然后创建独立任务。

## 4. 与任务进程的关系

任务创建时关联原始模型。

任务卡片展示：

- 主标题：应用的模板名称。
- 副标题：原始模型文件名称。

任务生成的面网格、体网格和执行日志归属于具体任务，而不是直接覆盖原始模型。

任务删除不影响原始模型资源。

## 5. 与几何标签的关系

如果现有模型导入及 Fluent 工作流已经支持几何面标签、Named Selections 或其他区域标识，应保留现有数据和引用关系。

模型资源模块负责提供必要的模型标识和已有标签信息。

实际标签识别、映射和网格设置仍由 Fluent 工作流负责。

V1 不额外开发一套独立的几何标签编辑系统。

## 6. 数据契约

建议定义 ModelAsset：

| 字段 | 用途 |
|---|---|
| model_id | 模型唯一标识 |
| original_filename | 原始文件名称 |
| display_name | 展示名称 |
| file_format | 文件格式 |
| storage_ref | 文件存储引用 |
| file_size | 文件大小 |
| checksum | 文件完整性校验 |
| import_status | 导入状态 |
| created_at | 导入时间 |
| deleted_at | 删除时间 |

如果现有系统存在模型版本机制，优先复用。

任务应保存本次实际使用的模型版本或不可变文件引用，保证后续能够追溯。

## 7. 异常处理

覆盖：

- 文件格式不支持。
- 文件损坏。
- 文件上传失败。
- 文件保存失败。
- 重复导入。
- 模型被任务引用时删除。
- 原始文件丢失。
- 模型引用失效。

重复导入是否进行文件去重，结合现有实现确定。

## 8. V1 验收标准

1. 可以从本地导入模型。
2. 导入成功后能够在模型列表中查看。
3. 模型具有稳定的唯一标识。
4. 原始文件与数据库记录保持关联。
5. 应用模板时可以选择已有模型。
6. 任务能够正确关联模型。
7. 任务输出与原始模型分开保存。
8. 删除任务不会影响原始模型。
9. 几何标签等已有元数据能够正常供 Fluent 工作流使用。
10. 模型资源异常能够得到明确反馈。

**模块原则：最大程度复用现有功能，不对原始模型管理体系进行不必要的重构。**

# Fluent AI｜业务实体与接口基线

**版本：V1 技术设计基线 0.1**  
**状态：已确认，可作为后续分期设计与实现依据**  
**依据：00、01、02-A～02-D、03、04、05、06、06-A～06-C；本仓库当前实现**

## 1. 用户目标与范围

用户从零件目录进入模板编辑，获得 Agent 工程建议，发布模板并应用到原始模型。每次应用创建独立任务。用户在任务区看到面网格、体网格两个主要节点及下一步操作提醒，点击任务后返回原 Fluent 工作流操作。

V1 支持多个任务记录，Fluent 执行由单一工作队列串行调度。当前任务等待用户操作时继续占用 Fluent；后续任务保持排队。此设计不表示多个 Fluent 实例并行运行。

Agent 推荐供用户核查并手动填写。Agent 不直接修改模板参数，不生成或注册工具。拓展台 V1 只提供说明页面。

## 2. 数据归属与关系

| 对象 | 唯一管理方 | 主要关系与规则 |
|---|---|---|
| 零件目录 `category_id` | 模板服务 | 目录有多个模板和一个共享能力空间；V1 仅一级目录 |
| 模板 `template_id` | 模板服务 | 属于一个目录；保存草稿与发布状态 |
| 模板版本 `revision_id` | 模板服务 | 保存完整 Fluent 配置快照；发布后编辑产生新草稿版本 |
| Agent `agent_id`、会话 `session_id` | Agent 服务 | 每模板独立身份和默认主会话；会话与参数不跨模板共享 |
| 模型配置 `model_profile_id` | 模型配置服务 | 可保存多配置，同一时刻一个全局有效配置；每次运行固定模型版本 |
| 工程案例与推荐 | 工程参数服务 | 归属模板会话；输入有单位、来源及确认状态；计算结果引用固定输入快照 |
| 模型 `model_id` | 模型资源服务 | 代表原始模型；任务通过 ID 引用，保留任务创建时文件名快照 |
| 任务 `task_id` | 任务服务 | 引用模板版本、模型及配置快照；一任务对应一次应用和独立工作流状态 |
| 执行会话 `session_id` | Fluent 执行服务 | 运行时会话单独记录；通过唯一任务关联，状态与任务记录关联 |
| 任务产物 `artifact_id` | 任务服务 | 属于单一任务，记录网格、日志、报告的存储引用和保留状态 |
| 能力资源及工具 | 能力服务 | 知识、规则和 Prompt 按目录共享；工具需注册且授权后方可调用 |

主要关系：`目录 → 模板 → 模板版本 → 任务 → 执行会话与产物`。每个模板另有关联独立 Agent 和会话。多个任务可以引用同一模型或同一模板版本，但共享引用不转移资源所有权。

## 3. 写入与状态规则

- 创建目录后初始化其共享能力空间。目录初始化失败时不返回可用成功状态；重试不得重复创建目录。
- 创建模板草稿时建立稳定模板 ID 和默认 Agent 会话。首次欢迎状态由后端保存。
- 保存草稿检查版本号；版本过期时返回冲突，前端提示刷新或重新加载，禁止静默覆盖。
- 发布产生不可变模板版本。编辑已发布模板先创建草稿；既有任务仍引用原版本。
- 每次“应用模板”创建新 `task_id`，保存模板版本、参数快照、模型引用和文件名快照。重复点击是否复用同一任务，由请求幂等键区分；相同请求键只创建一次。
- 任务有业务阶段和排队状态。界面主节点为面网格、体网格；详细步骤保留于后端事件。就绪状态只由 Fluent 服务确认的实际事件推进。
- 用户打开任务不清除提醒；确认执行对应步骤后，状态转为运行中并清除该操作的就绪标记。
- 任务结束后留在列表，直到用户删除。默认逻辑删除任务记录并保留产物及归属索引；清理选项只允许删除此任务独占的文件。
- 工程参数工作区和 Fluent 模板参数分别保存。修改工程输入不得自动改写 Fluent 参数。
- 已有任务引用的模型从可选列表隐藏，历史任务仍可解析原模型记录。模型原文件的托管、复制和外部修改检测尚需专门设计，不能仅靠保留数据库引用保证文件内容不可变。

建议任务内部至少记录 `queued / preparing / action_required / running / completed / failed / interrupted / deleted`。业务阶段记录当前面网格或体网格步骤，操作提醒记录 `next_action`。实际 API 采用既有 FastAPI 路由和项目命名风格；先定义 Pydantic 请求/响应模型，再接入 Electron IPC 与共享 TypeScript 类型。禁止 renderer 绕过 Electron preload 直接访问 sidecar。

跨模块服务边界按职责划分，不要求拆成多个进程：模板、Agent、全局模型配置、目录能力、工程参数及工具、模型资源、任务、Fluent 执行。V1 优先在现有 FastAPI sidecar 内扩展。

## 4. 安全、删除与迁移决策

- 删除目录前要求先移走或删除其下模板；不支持级联误删任务、会话和产物。
- 发布后编辑创建新的草稿版本；应用中的历史任务固定引用原版本。
- 草稿保存使用版本检查；并发冲突显式提示，禁止后写静默覆盖。
- 现有自动化预设迁移到“未分类”目录；保留原有数据库 ID、名称和参数内容。迁移失败须整体回滚或可重复安全重试。
- 被任务引用的模型从选择列表隐藏；原始记录和任务历史引用继续保留。
- 运行任务先请求停止；仅在 Fluent 执行服务确认停止后才允许删除。V1 不承诺强制中止正在运行的原子 Fluent 调用。
- Fluent 仍由单队列串行使用。等待人工操作的会话持有当前执行权，直到当前任务完成或用户明确停止；任务重启恢复仅恢复记录，确认 Fluent 实际状态后才可恢复操作。
- 工具权限在后端校验。文档、知识、Prompt 和模型输出均不得扩大权限或触发任意代码执行。

## 5. 验收场景

1. 创建两个目录及多个模板后，模板 ID、会话和工程参数保持隔离。
2. 修改全局模型后，新 Agent run 使用新配置；已有 run 与历史记录保持原配置。
3. 发布模板、创建任务、更新模板后，原任务仍显示并使用创建时版本。
4. 对同一模型两次应用模板得到两个独立任务；同时只允许队首任务使用 Fluent。
5. 当前任务等待生成面网格时，任务卡片显示面网格待操作；查看卡片不会清除提醒。
6. 任务停止或 sidecar 重启后，任务历史存在，活动状态被标记为中断，且不显示伪运行状态。
7. 默认删除任务保留网格、日志与归属索引；选择清理也不会影响原始模型或其他任务产物。
8. 跨模板提交其他会话 ID、未经授权工具 ID 或不匹配参数均由后端拒绝。

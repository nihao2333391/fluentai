## Implemented

- Raw workflow schema API:
  - `GET /api/meshing/schemas/{workflow_type}`.
- Shared TypeScript contracts for workflow tasks, nested arguments, compound child templates, and preset items.
- Business IPC, preload bridge, and Renderer Meshing service.
- Fluent-style Meshing automation editor with all real top-level workflow tasks in official order.
- Watertight editor preserves the 11-task workflow:
  - Import Geometry
  - Add Local Sizing
  - Generate the Surface Mesh
  - Describe Geometry
  - Apply Share Topology
  - Enclose Fluid Regions (Capping)
  - Update Boundaries
  - Create Regions
  - Update Regions
  - Add Boundary Layers
  - Generate the Volume Mesh
- Full workflow tabs for both Watertight Geometry and Fault-tolerant Meshing.
- Nested object arguments recursively expanded into editable leaf settings with their real edit paths.
- Read-only and inactive/status settings retained under a collapsed advanced section.
- Compound child presets can be created multiple times with stable instance IDs and user-defined names.
- The managed control-name argument is written automatically from the child preset name.
- Watertight compound child templates:

| Compound task         | Template source                   |
| --------------------- | --------------------------------- |
| Add Local Sizing      | Official parent command arguments |
| Enclose Fluid Regions | Official parent command arguments |
| Add Boundary Layers   | Official `add_child_and_update`   |

- Fault-tolerant compound templates captured for 10 compound tasks. Two remain explicitly blocked rather than fabricated:
  - Identify Construction Surfaces
  - Create Local Refinement Regions
- Reload now re-fetches the selected workflow schema instead of assigning the same state value.
- Save flow builds a versioned preset, validates every item against the schema API, then creates the Meshing automation.

## Current Boundary

M8.3 provides editing and preset persistence only. It does not yet open a target model, create child tasks, write workflow arguments, or read them back.

The next milestone is the Meshing apply engine. It must:

- Load the target model.
- Validate required boundary, zone, region, and label names exactly.
- Create compound child tasks in the same order as the preset.
- Write preset arguments through the official workflow API.
- Read every written value back.
- Stop before surface or volume mesh generation.
- Persist jobs and sync logs.

## Gate Decision

M8.3 is accepted. Proceed to M8.4 Meshing apply engine.
